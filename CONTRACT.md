# catchledger contract

This contract is the executable spec for catchledger. Every obligation below maps to at least one named test in the test suite. An obligation is met only when its tests pass.

## Ground and probes

Catchledger prices checks and secondbill prices work. Catchledger joins a local export of completed workflow runs with a local Git history for one repository and builds a conservative scorecard for each check. It computes evidence from those local inputs and never reaches a network in the tool or in its tests.

The workflow run probe used synthetic records in the shape exported for workflow runs. A run record carries an identifier and a check name and a head commit and a status and a conclusion and creation and start and update timestamps. The probe found that the start timestamp can stand after the creation timestamp and that the update timestamp is the end used for a completed run. An export can carry those records as a bare list or inside an object under the workflow runs field. The probe treated a failure conclusion as a block and treated a success conclusion as a pass and left every other completed conclusion as neither a block nor a validating pass.

The Git history probe used a synthetic local repository with an added file and a modified file and a renamed file. The probe command was git log in reverse topological order with rename detection and name status output and a record that carries the commit hash and its parents and its commit timestamp and its subject before its changed paths. The probe found an empty parent list on the root commit and one parent on each ordinary later commit. It found an added path on an added line and a modified path on a modified line and both the old and new paths on a rename line. A local clone read through that command and an export captured from that command produce the same commit records.

The canaryfield probe used a synthetic catch table in the shape written by canaryfield. That document carries a gates list and rows in which each row names a seed and a defect class and gives one planted result for each gate. The result words are caught and waved-through and not-applicable and gate-broken. Catchledger matches a check to a gate by exact name and preserves the seed rows as evidence when a match exists.

The attribution ground is deliberately narrow. A blocked commit supplies the flagged paths from the paths its own history record changes. A later change counts as a fix only when it changes one of those paths and stands in the ancestry between the blocked commit and a later successful run of the same check. The subject of a later commit is not evidence. A successful run of the same check on the blocked commit itself is stronger evidence that the block did not identify a durable defect and it takes precedence over later descendant evidence. A history record that carries no changed paths for a blocked commit leaves no flagged code to follow, so a block on that commit earns no catch. The dominant instance of that limit is a blocked merge commit, because the probed Git log shape emits no change lines for a merge commit and a blocked merge therefore carries no flagged paths at all. Such a block can still earn the false block reading, because a successful run of the same check on the blocked commit itself needs no flagged code and keeps the precedence this ground already states. That limit is stated here rather than hidden in the code.

An empty Git history export parses to zero commit records rather than failing, so every block in a ledger built on it stands unattributed with the reason that its blocked commit is missing from the Git history. Two limits of the clone reading stand beside that one. The local git subprocess runs with no timeout, so a hung local git can hold a reading open. A path that git renders in its quoted form under its core.quotePath setting is recorded in that quoted form rather than decoded.

## Slice 2 obligations

Obligation CL2-1 covers workflow run ingestion. The ingester accepts a bare list of run records or an object with a workflow runs list and ignores a record whose status is present and is not completed and ignores a record with no conclusion. A completed record must carry an identifier and a nonempty check name and a head commit and a conclusion and creation and update timestamps and it may carry a start timestamp. The ingester normalizes identifiers to strings and check conclusions and head commits to lowercase where those fields carry words or hashes and raises a catchledger error for a malformed completed record rather than guessing. An exact duplicate of a completed run is counted once and a conflicting record with the same identifier is refused. Proven by test_ci_envelope_and_bare_list_ingest_the_same_runs and test_incomplete_and_malformed_runs_are_not_guessed and test_exact_duplicate_runs_count_once_and_conflicts_are_refused.

Obligation CL2-2 covers Git history ingestion. The parser reads records in the probed git log order and preserves that order and reads the hash and parents and commit timestamp and subject and every changed path for each commit and reads both paths from a rename or copy line. Reading a local clone invokes git log with the same reverse topological order and rename detection and name status shape and produces records equal to the records parsed from an export of that clone. A malformed export is refused with a catchledger error and a path that is not a readable local Git repository is refused with a catchledger error. Proven by test_git_log_export_parses_records_and_renames and test_local_clone_and_export_produce_the_same_records and test_malformed_git_history_is_refused.

Obligation CL2-3 covers the per check scorecard. Checks are sorted by name and only completed runs enter a scorecard. Fires counts completed runs and blocks counts completed failure conclusions and judged commits counts distinct head commits. A flaky commit is a distinct head commit whose completed runs carry more than one conclusion and it is counted once no matter how many runs repeat a conclusion. Flake rate is flaky commits divided by judged commits. Runtime seconds sums the nonnegative whole second distance from the start timestamp or the creation timestamp when no start timestamp stands to the update timestamp and a negative distance contributes zero. Total cost is runtime seconds divided by sixty and multiplied by the configured price per minute. Cost per catch is total cost divided by catches when catches is positive and is null when catches is zero. Rates and minute and money values are rounded to six decimal places with half up rounding. Proven by test_scorecard_counts_fires_blocks_and_runtime and test_flake_is_counted_once_per_commit and test_cost_per_catch_is_null_without_a_catch and test_cost_per_catch_uses_total_check_cost.

Obligation CL2-4 covers a true catch. Every failure run creates exactly one catch record. The flagged paths are every path the blocked commit changes in the Git history. A record is a catch only when a later completed successful run of the same check judges a descendant of the blocked commit and at least one commit in the ancestry interval after the blocked commit and through the successful commit changes a flagged path at or before the successful run starts. The catch evidence names the flagged paths and the fix commits in history order and the validating run. No subject word and no change outside the flagged paths can substitute for that evidence. Proven by test_block_followed_by_flagged_fix_and_success_is_a_catch and test_block_followed_by_fix_outside_flagged_code_is_not_a_catch and test_flagged_change_without_a_later_success_is_not_a_catch and test_catch_counts_sum_with_all_block_outcomes.

Obligation CL2-5 covers a false block from a bare retry. A later completed successful run of the same check on the same head commit as a block makes that block a false block even when later descendant evidence also exists. The evidence names the same commit validating run and carries no fix commits. A later successful run on a descendant commit is not a bare retry. False block rate is false blocks divided by blocks when blocks is positive and is null when blocks is zero. Proven by test_block_followed_by_bare_retry_counts_against_the_check and test_bare_retry_takes_precedence_over_descendant_fix_evidence and test_false_block_rate_uses_blocks_as_the_denominator.

Obligation CL2-6 covers unattributed blocks. A block is unattributed whenever it earns neither the catch evidence in CL2-4 nor the false block evidence in CL2-5. Its evidence names one reason from a fixed set that covers a blocked commit missing from the Git history and a flagged change without a validating success and a later descendant success without a flagged fix and a later outcome without a validating success and no later outcome. An unattributed block is never silently moved into catches or false blocks and the three outcome counts always sum to blocks. Proven by test_block_with_no_later_outcome_is_unattributed and test_missing_blocked_commit_is_unattributed and test_later_success_without_flagged_fix_is_unattributed and test_catch_counts_sum_with_all_block_outcomes.

Obligation CL2-7 covers the evidence pack format. The format name is catchledger-pack/1. One pack is built for each check in the ledger and each pack carries the format name and the repository label and the check name and the exact scorecard and the exact catch record and the exact canaryfield result value and the false block rate and the exact pricing record and the exact source record from its ledger. Validation rebuilds the expected pack from the ledger and refuses a supplied pack when any field differs or when a field is missing or when an unexpected field stands in the pack. Proven by test_evidence_pack_carries_the_complete_check_record and test_pack_validation_refuses_a_tampered_scorecard and test_pack_validation_refuses_tampered_evidence_and_metadata.

Obligation CL2-8 covers canaryfield planted catch evidence. The optional canaryfield input must be an object with a gates list and a rows list and each matched row must carry a seed and a name and a defect class and a planted result for the gate. For a check whose exact name stands in the gates list the pack carries a normalized object with the source shape name and the gate name and counts for all four planted results and the matched rows sorted by seed. For a check with no exact gate match and for every check when no canaryfield input is supplied the pack value is null. A malformed canaryfield document is refused rather than partially read. Proven by test_canaryfield_results_are_normalized_for_the_matching_check and test_canaryfield_results_are_null_without_an_exact_gate and test_malformed_canaryfield_results_are_refused.

Obligation CL2-9 covers deterministic output. The command line requires one local workflow run export and exactly one local Git history source chosen from an export file and a local clone path and it writes one JSON ledger and one markdown report and one evidence pack file for each check. JSON output uses sorted keys and two space indentation and one trailing newline. Checks and catch records and pack files have stable sorted orders and no output carries a wall clock time or a local filesystem path. Running the command twice on the same inputs produces byte identical ledger and report and pack bytes. Proven by test_cli_writes_deterministic_outputs and test_cli_accepts_a_local_clone and test_ledger_and_report_carry_no_local_paths.

Obligation CL2-10 covers the offline boundary. The tool reads only the local files and the local Git repository named on its command line and invokes only the local git executable for a clone input. A remote location is not fetched and a missing local input is refused with a catchledger error. The test suite builds every fixture synthetically and uses no network. Proven by test_missing_inputs_are_refused and test_local_clone_and_export_produce_the_same_records and test_cli_writes_deterministic_outputs.

## Round 1 review fixes

The Round 1 red team and the Round 1 two axis review both returned conditional verdicts on slice 2, and the obligations below record the repairs. Obligation FIX-1 covers the horizon of the catch search and amends CL2-4. The bare retry reading of CL2-5 is applied first. The search for a catch then stops at the first later successful run of the same check on a descendant of the blocked commit, and that run is the horizon of the search. A catch stands only when a flagged change stands in the ancestry interval through the horizon commit and at or before the horizon run starts. When the horizon run carries no qualifying flagged change the block earns no catch from any later fix, because the check already stood green while the flagged code stood unfixed. A later successful run on a commit that does not descend from the blocked commit is not a horizon and does not end the search. Proven by test_descendant_success_without_a_fix_ends_the_catch_search.

Obligation FIX-2 covers the precedence among the unattributed reasons and amends CL2-6. When a later successful run of the same check stands on a descendant of the blocked commit, the reason is the later descendant success without a flagged fix, even when an unvalidated flagged change also stands later and even when the only flagged change in the interval was committed after that successful run started. The flagged change without a validating success reason stands only when no later successful run stands on a descendant. The remaining reasons keep the order CL2-6 states. Proven by test_reason_prefers_the_descendant_success_over_a_later_flagged_change and test_fix_committed_after_the_validating_run_started_earns_no_catch, and the second of those also pins the timing edge of CL2-4, under which a flagged change committed after the validating run started earns no catch.

Obligation FIX-3 covers the ground record for blocks whose commit carries no changed paths. The ground now states that such a block earns no catch and that a blocked merge commit is the dominant instance of the limit, because the probed Git log shape emits no change lines for a merge commit. Such a block still earns the false block reading of CL2-5 when a successful run of the same check stands on the blocked commit itself. Proven by test_blocked_commit_without_changed_paths_still_earns_a_false_block and test_blocked_merge_commit_earns_no_catch.

Obligation FIX-4 covers the flagged path matching reading and amends CL2-4. Matching between the flagged paths and the paths a later commit changes is raw string matching over the recorded path strings. A rename or copy line inside the interval carries both of its path strings, so a rename of a flagged path inside the interval intersects the flagged set on either name. A fix applied only under a name the flagged set does not carry is missed and the block earns no catch from it, and that miss is the conservative direction and stands as a named limit of this slice. Obligation FIX-5 covers three sentences of CL2-3 that stood without a discriminating pin. Obligation FIX-6 covers three further proof gaps the two axis review named. Obligation FIX-7 covers the history window and amends CL2-7. Obligation FIX-8 covers the independence of a built pack from its ledger. Obligation FIX-9 covers the normalized canaryfield row shape and amends CL2-8. Each normalized row carries exactly the seed and the name and the defect class and the result and the planted files. The planted files value is the row planted files list when that list stands, and a one item list holding the row planted file string when only that string stands, and an empty list when neither stands.
